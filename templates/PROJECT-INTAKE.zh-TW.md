# ai-dev 新專案啟動表

用途：下次用 [ai-dev 範本](https://github.com/gg-dot1980/ai-dev) 開新專案時，複製這份空白表。先填 1–5 即可起草規格與第一次概念驗證（POC）；6–8 可以先寫「待定」，在相關操作前再確認。

| 欄位 | 怎麼填 | 你的填寫 |
| --- | --- | --- |
| 1. 專案名稱與一句話目標 | 要做什麼、解決什麼問題？ |  |
| 2. 使用者與使用情境 | 誰會用？最常完成哪件事？ |  |
| 3. 第一版範圍 | 必做的 1–3 項功能；這一版明確不做什麼？ |  |
| 4. 驗收條件 | 怎樣算成功？例如固定樣本 20 筆，至少 18 筆正確，並保留失敗明細。 |  |
| 5. 限制與資料來源 | 有無既有程式或資料？哪些可公開？有哪些成本、平台或 API 限制？ |  |
| 6. Repo 與執行環境 | 新建或沿用哪個 repo？公開或私人？在哪裡開發、建置與測試？ |  |
| 7. 分工與權限 | 誰是擁有者、實作者、獨立審查者？外部 AI 或人類能提交、合併或部署到哪一層？ |  |
| 8. 測試與部署 | 要測哪些環境？測試站和正式站在哪？誰核准？如何驗證上線並回滾？ |  |

不填密碼、金鑰或私有資料。填表不等於授權公開、合併或部署。資訊若已在對話或專案文件裡提供，不必再填一次。

AI 啟動新專案時（不是單純瀏覽或維護既有專案），必須向使用者呈現全部八題或預填答案供確認，直接詢問每個缺漏或未確認的答案，可合併提問，並記錄回覆及待辦。已明確提供的答案沿用，不重複詢問、不猜測、不推定授權。第 1–5 題確認前，不得把範圍或 POC 計畫當作已議定，也不得把實作當作已批准；第 6–8 題可明確標記待定，但在相關 repo、分享、合併或部署操作前須解決。使用者無法回覆時，列出未答項並停在相關步驟之前。
